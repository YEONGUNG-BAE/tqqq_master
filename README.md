# TQQQ/QQQ 원화 입금 자동화: 구현 1차

2026-10-15. **현재 단계는 오프라인 검증과 실계좌 읽기 연결 준비입니다. 실거래 검증·설치·가동은 끝나지 않았습니다.** 기본 설정은 `observe`이며 환전·매수·매도·취소를 전송하지 않습니다. 기존 QQQM·버크셔는 그대로 둡니다.

구현한 흐름은 `원화 여유 현금 → 환전 → 현재 목표 ETF 매수`, `전환 신호 → 기존 ETF 매도 → 체결·잔고 확인 → 목표 ETF 매수`입니다. 주문·환전 전 SQLite에 의도와 전송 시작을 따로 기록합니다. 응답이 끊기면 재전송하지 않고 증권사 주문·환전 기록과 대조해 자동으로 복구합니다. 대조할 근거가 없으면 신규 주문을 보류하고, 오래 해소되지 않으면 거래 잠금으로 알립니다(아래 '자동 복구와 잠금'). 정수 주식만 매수하므로 1주 미만의 달러 잔액이 남습니다.

이번 작업은 기존 초안을 이어받아 **저장되는 모의 계좌·납입/전환 반복 실행·중단 후 재개·과거 주문 조회 복구·정확한 임계값 비교**를 보강한 버전입니다. 상세한 완료 범위와 다음 구현 순서는 [WORK_STATUS.md](WORK_STATUS.md), 고정 규칙과 실행 명령은 [CLAUDE.md](CLAUDE.md)를 참고합니다. 증권사 선정 의견과 별개로 공통 실행 엔진은 브로커 연결부를 교체할 수 있게 유지합니다.

## 전략과 체결 방식

- QQQ의 분할만 조정한 종가, 배당 미조정.
- 당일을 포함한 최근 252거래일 최고 **종가** 대비 하락률.
- TQQQ 상태에서 −15% 이하: QQQ로 전환.
- QQQ 상태에서 −12% 이상: TQQQ로 전환.
- 사이 구간은 직전 전략 상태 유지. 실제 보유 상태와 전략 상태는 따로 기록.
- 고점 만료 재진입을 유지하고 진단 항목으로 기록.

원래 비교 백테스트의 체결은 **다음 미국 거래일 종가**입니다. 이 초안의 메리츠 실행 후보는 **다음 거래일 개장 1~15분 사이 지정가 순차 주문**입니다. 시장가 주문도, 동시 시가 체결도 아닙니다. 기존 다음 날 시가 민감도는 참고 자료이며 이 코드의 실제 체결 결과를 재현한 검증은 아닙니다. `open_window_execution` 검증 항목을 통과하기 전에는 실거래에 사용하지 않습니다. 사용자의 후속 요청에 따라 종가 주문을 지원하는 브로커도 조사했으며 [BROKER_REVIEW.md](BROKER_REVIEW.md)에 기록했습니다. 체결 방식을 확정한 구현으로 오해하면 안 됩니다.

## Mac에서 모의 실행

Python 3.11 이상이 필요합니다. 압축을 풀고 그 폴더에서 실행합니다.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m autotrader demo --state demo_output
```

`demo`는 API 키가 필요 없고 네트워크를 사용하지 않습니다. 원화 1천만 원·환율 1,400원·TQQQ 호가 70달러를 **가정한 기능 시연**입니다. 실제 시세나 수익률 예측이 아닙니다. 출력 폴더가 있으면 다른 이름으로 실행합니다.

오프라인 검증: **81개 테스트 통과** (2026-10-15, Python 3.14.5 · exchange-calendars 4.12 · pandas 2.3.3 · NumPy 2.5.4). 환전·주문 응답 유실, 재시작, 일부 체결, 취소 요청과 취소 확정의 구분, 매도 후 잔고 반영, 매수 가능 금액 제한, 보유 종목 보호, 배당 조정 가격 불일치, 분할 재조정, 미국 시차·휴장·단축장을 확인했습니다. 이번에는 날짜를 넘긴 전량 체결 복구, 여러 페이지의 주문 이력, 다른 키의 토큰·상태 재사용 방지, 장외 취소 전송 차단, Decimal 경계값과 장기간 누락 이력도 추가 검증했습니다. 네트워크와 실제 계좌는 검증하지 않았습니다.

## 저장되는 모의 운용과 재개

세 가지 예제를 제공합니다. 모두 **가상 종가·가상 호가·가상 체결**이며 성과 백테스트가 아닙니다. 주문 호가는 의도적으로 일정하게 두었고, 신호용 종가는 전환 과정을 점검하도록 만든 값입니다. 현재가·미래 수익률·실제 체결 가능성에 관한 자료로 쓰지 않습니다.

| 예제 | 가상 납입 | 기간 |
|---|---|---|
| `examples/father_monthly.json` | 월 10만 원, 총 30만 원 | 43거래일 |
| `examples/child_lump_sum.json` | 첫날 200만 원만 납입 | 43거래일 |
| `examples/self_irregular.json` | 100만·23만·134만·17만 원 비정기 납입 | 43거래일 |

```sh
.venv/bin/python -m autotrader replay --scenario examples/self_irregular.json --state paper_self --sessions 10
.venv/bin/python -m autotrader replay --scenario examples/self_irregular.json --state paper_self
```

첫 명령은 10거래일까지만 실행하고 종료합니다. 두 번째는 같은 DB에서 이어서 실행합니다. 끝난 후 동일 명령을 반복해도 납입·주문을 다시 만들지 않습니다. 매 거래일마다 모의 브로커와 엔진을 새로 생성해 저장된 상태로 복구합니다. `paper_self/replay.json`에 결과가 저장됩니다. 다른 예제는 각각 다른 상태 폴더를 사용합니다.

시나리오 파일을 바꿨다면 새 상태 폴더를 사용합니다. 동일 납입 식별자로 금액을 바꾸거나, 관찰/실거래 상태 폴더를 모의 계좌에 쓰면 중단합니다. 실제 납입액의 끝자리로 운용 방식을 추측하지 않으며, 입금 주기와 무관하게 실제 투자 가능 현금으로 정수 수량을 계산합니다.

## 실계좌 읽기 연결

메리츠 OpenAPI 신청·키 발급·해외주식 거래 등록·실시간 시세 이용 조건을 계좌에서 준비해야 합니다. 키는 자신의 Mac에만 저장합니다.

```sh
cp config.example.json config.json
cp secrets.example.env secrets.env
chmod 600 secrets.env
```

### 키와 개인 설정을 넣는 곳

실제 값은 아래 두 파일에만 넣습니다. 두 파일은 `.gitignore`에 들어 있어 Git에 올라가지 않습니다. 예제 파일(`*.example.*`)에는 실제 값을 넣지 마세요. 계좌번호는 어디에도 넣을 필요가 없습니다.

| 파일 | 항목 | 내용 |
|---|---|---|
| `secrets.env` | `MERITZ_CLIENT_ID`, `MERITZ_CLIENT_SECRET` | 메리츠 OpenAPI 포털에서 발급받은 앱 Key와 앱 비밀 Key (필수) |
| `secrets.env` | `MERITZ_MAC_ADDRESS` | 선택. 콜론 없는 12자리 대문자 MAC. 비우면 이 Mac 값을 자동 사용 |
| `secrets.env` | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | 선택. 텔레그램 알림 |
| `secrets.env` | `ALERT_SMTP_*`, `ALERT_FROM`, `ALERT_TO` | 선택. 메일 알림 |
| `config.json` | `execution.reservation_lookup_start` | 계좌 개설일(또는 그 이전)을 `YYYYMMDD`로. 비우면 live 신규 실행이 차단됨 |
| `config.json` | `state_dir`, `execution.mode`, `verified` | 상태 폴더와 실행 모드. 기본 `observe`이며, `verified`는 실제 검증 전에 true로 바꾸지 않음 |

`secrets.env`는 권한 600이어야 읽습니다(아니면 실행이 멈춤). 키 값을 채팅이나 이슈, 커밋에 붙여넣지 마세요. 실행 중 만들어지는 `token.json`, `state*/`, `paper_*/`, `*.sqlite*`, `logs/`도 Git에서 제외됩니다.

### 공식 API 명세 받기 (선택, 테스트용)

명세 원본은 재배포 가능 여부를 확인하지 못해 저장소에 넣지 않았습니다. 요청 필드 계약 테스트까지 돌리려면 공식 포털에서 직접 받습니다.

```sh
curl -fsSL https://openapi.imeritz.com/api-spec/download/json -o vendor/meritz-portal-20261015.json
shasum -a 256 vendor/meritz-portal-20261015.json   # vendor/SCHEMA_SOURCE.json의 sha256과 비교
```

해시가 다르면 포털 명세가 바뀐 것입니다. 이 파일이 없어도 나머지 테스트는 실행되며, 명세 대조 테스트 2개만 건너뜁니다. 메리츠 공식 GitHub 저장소: <https://github.com/meritz-securities/open-api>

이후:

```sh
.venv/bin/python -m autotrader doctor --config config.json
.venv/bin/python -m autotrader run --config config.json
.venv/bin/python -m autotrader status --config config.json
```

`doctor`는 읽기 전용 진단입니다. GET 조회와 토큰 발급만 보내며, 설정이 live여도 환전·매수·매도·정정·취소를 보내지 않습니다. 항목별로 실패해도 나머지를 보여줍니다.

- 인증·연결, 원화 가용 현금, USD 예수금·주문가능금액, 신용·미수
- 보유 종목(일반/소수/대출), 당일 미체결(엔진 추적 여부), 예약주문(활성 예약이 있거나 조회가 실패하면 엔진이 신규 환전·주문을 차단, 예약은 취소하지 않음. `execution.reservation_lookup_start`에 계좌 개설일을 넣어야 전체 조회로 인정되며, 없으면 live 신규 실행 차단)
- 고객 적용 환율·스프레드·할인율, 매매 수수료는 조회 API가 없어 `not_verified`
- 최신 완료 거래일·종가 기준 대조, 252일 고점·하락률·목표·전환 사유
- 미국 정규장·증권사 장운영 상태, 현재 엔진의 주문·환전 가능 여부(정규장은 거래소 달력·증권사 현재 구간 시각·현재 시각이 모두 맞을 때만 인정)
- 주문 없는 관찰 계획: 예정 환전액, 목표 종목, 정수 매수 수량, 예상 잔액 (엔진과 같은 계산 함수)
- 멈춤·제한 사유. QQQM·BRK.B 등 기존 보유가 있어도 진단은 표시하고, 자동 매도·전환하지 않습니다.

요약은 터미널에, 민감정보를 뺀 JSON은 `state_observe/doctor/latest.json`에 저장됩니다(`--json`으로 출력 가능). 키가 없으면 계좌 항목을 건너뛰고 로컬 이력 신호를 `unverified`로 표시합니다. 한국 낮(환전 시간)과 미국 개장 직후에 한 번씩 실행하면 환율 검사와 실시간 호가 검사를 각각 확인할 수 있습니다.

기본 상태에서 기존 QQQM·BRK.B가 있으면 `run`은 그 종목을 건드리지 않고 멈춥니다. 현재 보유분을 유지하려는 결정에 따른 설정입니다. `run` observe의 실제 처리 범위는 [WORK_STATUS.md](WORK_STATUS.md)에 정리했습니다.

## 실거래 연결 검증에서 남은 항목

1. **가격 기준:** 메리츠 일봉의 수정주가 옵션은 명세상 동일한 데이터를 줄 수 있습니다. 배당 미조정·분할 조정 기준을 이력과 대조해야 합니다. 겹치는 100개 이상 종가가 다르면 코드가 멈춥니다. 완전히 균일한 2:1 등 지원 비율의 변경만 이력 전체에 재조정하고 기록합니다. 임의 변경·배당 조정·작은 이력 오류는 자동으로 덮지 않습니다. 데이터 공급자 오류를 해결한 뒤 다시 검증합니다.
2. **주문 자금과 수수료:** 같은 계좌의 API 할인 적용, 재매매 가능 금액, 통합증거금·타통화 증거금·자동 RP의 영향을 확인합니다. 명세의 주문 가능 금액은 수수료가 포함되지 않아 여유분을 뺍니다. 코드가 조회하는 외화 추정 예수금·주문 가능 금액의 실제 의미도 대조해야 합니다.
3. **체결 상태:** 실제 계좌에서 부분 체결·취소 확정·거부·잔고 반영 응답을 확인합니다. 현재 모의 테스트는 명세에 따른 응답을 사용했습니다. 원주문의 취소 확정 필드가 계좌에서 어떻게 갱신되는지 검증이 필요합니다.
4. **실행 방식:** 종가 양방향 체결 가능성을 먼저 검토하고, 개장 직후 후보를 택한다면 그 가격·지연·슬리피지로 비교합니다. 임계값을 새로 최적화하는 작업은 포함하지 않습니다.
5. **알림과 가동:** Mac 알림, 자신의 주소로 보내는 메일, 텔레그램(선택)으로 결과를 받습니다. 메일과 텔레그램은 직접 설정하고 전달 여부를 검증해야 합니다. Mac이 꺼지거나 인터넷이 완전히 끊기면 자체 알림도 전달할 수 없으므로 별도 가동 상태 감시가 필요합니다.

위 검증 후 실제 운용을 선택한다면 `execution.mode`와 **별도의** `state_dir`를 `live`, `state_live`로 바꾸고, 검증한 `verified` 항목을 true로 기록합니다. 검증했다고 표시하는 것만으로 실제 검증이 되지는 않습니다. API 연결·실거래 시험을 이 환경에서 대신 수행하지 않았습니다.

`migrate_symbols`는 기본 빈 배열입니다. 이후 기존 종목을 전환하기로 결정할 때만 `QQQM`, `BRK.B`를 명시적으로 지정합니다. 그 외 종목·소수점 잔고·신용·대출·알 수 없는 미체결 주문이 발견되면 자동 처리를 멈춥니다. 은행·생활비·주택자금과 분리된 투자 계좌를 전제로 합니다.

## 예약 실행과 장애 처리

검증 전에도 읽기 전용 관찰을 예약할 수 있습니다. 다음 명령은 설정 파일만 생성합니다.

```sh
.venv/bin/python install_launchd.py
```

관찰 예약을 자신의 Mac 사용자 세션에 등록할 때:

```sh
mkdir -p "$HOME/Library/LaunchAgents"
cp local.tqqq.observer.plist "$HOME/Library/LaunchAgents/"
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/local.tqqq.observer.plist"
```

중지:

```sh
launchctl bootout "gui/$(id -u)/local.tqqq.observer"
```

60초마다 한 번 실행하지만 투자 신호는 완료된 일봉마다 한 번 갱신합니다. 신호 계산에 장중 가격을 사용하지 않습니다. 환전은 평일 09:00~15:20 가운데 한국거래소(XKRX) 휴장일을 뺀 보수적인 후보 구간에서만 시도합니다. 한국거래소 개장일이 메리츠 환전 가능일과 같다고 확인한 것은 아니며, 실제 가능 여부는 계좌 응답으로 판단합니다. Mac은 전원 연결·잠자기 해제·재부팅 후 로그인·네트워크가 유지되어야 합니다. LaunchAgent는 로그인 전부터 가동되는 시스템 서비스가 아닙니다.

### 자동 복구와 잠금

장중 복구로 체결되는 가격은 공식 시가나 기존 연구의 다음 날 종가와 다릅니다. 과거에 전환이 다음 날까지 늦어져 손실이 난 사례는 당일 복구를 지원하는 근거일 뿐, 장중 체결이 항상 다음 날 체결보다 낫다는 보장은 아닙니다. 봇은 신호 일자, 전환 의도 생성 시각, 주문 시각, 호가 시각, 지정가, 체결 수량, 이월 사유를 내부 기록에 남깁니다. 임계값을 다시 최적화하지는 않습니다. 장마감 주문(MOC)은 API 지원과 접수·취소 조건이 확인되지 않아 쓰지 않습니다.


정상 운용 중에는 승인 버튼이나 수동 선택이 필요 없습니다. 매 실행(60초)마다 최신 확정 신호와 실제 잔고·미체결·가용 자금을 다시 읽고, 필요한 작업을 하나씩 계산합니다. 우선순위는 다음과 같습니다.

1. 이미 보낸 요청의 상태 확정
2. 목표와 충돌하는 봇 주문 취소
3. 전환
4. 남는 자금으로 같은 목표 매수

| 상황 | 동작 |
|---|---|
| 요청 응답 유실·불완전 응답 | 재전송하지 않음. 응답 코드가 없는 응답도 여기에 포함. 증권사 주문내역·환전내역에서 종목·방향·수량·가격(환전은 방향·금액)과 시각이 맞는 기록이 **정확히 1건**이면 그 요청으로 확정. 0건이면 계속 대조(빈 조회는 미접수 근거가 아님). 2건 이상이면 임의로 고르지 않고 잠금 |
| 주문 거부 응답 | 명세상 `0001` 외 응답 코드는 미접수. 재시도 대기(15초부터 두 배씩, 최대 120초, 지터) 후 최신 상태로 다시 계산. 연속 5회면 잠금 |
| 환전 오류 응답 | 명세에 처리 전 거부로 적힌 코드(`7668`, `IGW50004`, `EGW00121`, `EGW00200`)만 미처리로 보고 재시도. 그 밖의 코드는 실행됐을 수 있으므로 불명으로 두고 환전내역으로만 확정. 내역이 늦게 보여도 다시 환전하지 않음 |
| 신호 갱신 실패 | 신규 주문·환전만 보류. 이미 보낸 자기 주문의 조회·체결 대조·시간 초과 취소는 계속 |
| 느린 조회·전송 지연 | 토큰 발급과 호출 간격 대기가 끝난 뒤 HTTP 전송 직전에 현재 시각으로 실행창·환전 시간과 호가 유효성을 다시 검사. 그 사이 마감되었거나 호가가 낡았으면 보내지 않음(실패로 세지 않음) |
| 경고·보류 응답 | 자동 확인하지 않고 잠금 |
| 부분 체결·취소 | 누적 체결량은 줄어들지 않음. 취소 요청과 취소 확정을 구분. 최종 체결분만 보유 대조에 반영 |
| 매도대금 반영 지연 | 실행창 안에서 재조회. 실행창을 넘기면 이월로 기록하고 다음 실행창에서 다시 계산 |
| 목표 변경 | 이전 목표의 봇 미체결은 취소 후 진행. 남은 보유를 되사기 위한 왕복 매매는 하지 않음 |
| 개장 실행창을 놓친 전환 | 확정 신호에 따른 전환(TQQQ 이탈·복귀 모두)은 같은 정규장 안에서 마감 10분 전까지 복구. 전환 의도에 기록된 기존 보유와 실제 전환 매도대금만 사용하며, 신규 입금·유휴 현금은 다음 개장 실행창까지 투자하지 않음. 다시 주문할 때는 남은 시간과 남은 주문 상한으로 나눈 간격(최소 300초)을 둠. 마감 전에 끝나지 못하면 이월하고 다음 정규장에서 다시 계산 |
| 마감을 넘긴 미체결·취소 미확정 | 상태를 그대로 보존하고 다음 조회 때 대조. 밤·휴장일이 지났다는 이유만으로 잠그지 않으며, 다음 정규장에서도 종료로 확인되지 않을 때만 잠금 |
| 예약주문·타 주문·정규장 미확인·시세 노후 | 신규 주문만 보류. 자기 주문의 상태 확인은 먼저 계속 |
| 토큰 만료 | 다음 조회에서 자동 재발급(Refresh Token 없음, client_credentials 재발급). 발급 거절이 3회 연속이면 잠금 |
| 상태 DB 손상 | 모든 요청 중단, `journal_unusable.json` 생성. 자동으로 초기화하지 않음 |

**일시 보류**는 조건이 해소되면 다음 실행에서 자동으로 풀립니다. **거래 잠금**(해소 불가)은 다음 경우에 걸리며, 조회·대조만 계속하고 새 주문·환전·취소는 보내지 않습니다.

- 접수 여부가 6시간 넘게 불명
- 귀속할 수 없는 기록
- 반복 거부
- 인증 거절
- 체결·보유 모순이 2시간 넘게 지속

잠금 알림에는 필요한 조치가 함께 표시됩니다. 앱에서 확인한 뒤 다음 명령을 실행합니다. 이 명령들은 브로커에 아무 요청도 보내지 않습니다.

```sh
.venv/bin/python -m autotrader status --config config.json          # 잠금·보류·진행 중 요청·장부 진단
.venv/bin/python -m autotrader resolve --config config.json \
  --action 확인한_ACTION_ID --outcome account_reconciled \
  --note '앱에서 실제 체결과 잔고를 확인한 내용'
.venv/bin/python -m autotrader unlock --config config.json --note '원인과 조치'
```

`resolve`는 접수 여부를 직접 확인한 요청 하나를 정리합니다. 실제로 전송되지 않았음을 확인했으면 `--outcome confirmed_not_sent`를 씁니다. `unlock`은 결과가 불명확한 요청이 남아 있으면 거절됩니다. 결론을 추정해서 실행하면 안 됩니다.

같은 계좌(API 키)에는 한 번에 한 프로세스만 실행됩니다. 상태 폴더별 잠금과 별도로 `~/Library/Application Support/tqqq_auto/locks/`에 계좌별 OS 잠금을 둡니다(`account_lock_dir`로 변경 가능). 상태 DB도 진행 중인 요청을 한 건만 허용합니다.

**알림:** 다음 상황에서 알림을 보냅니다. 같은 원인은 재시작해도 반복해서 보내지 않습니다. 성공·실패는 채널별로 기록합니다. 실패한 채널에는 같은 내용을 저장해 두었다가, 매 실행마다 30분 간격으로 최대 24시간 다시 보냅니다. 정상·완료처럼 한 번만 생기는 알림도 포함됩니다.

- 정상(하루 1회)
- 목표 정렬 완료
- 보류
- 복구
- 이월
- 잠금

알림에는 키·토큰·계좌·주문번호·잔고·금액을 넣지 않습니다. 텔레그램은 `secrets.env`에 `TELEGRAM_BOT_TOKEN`과 `TELEGRAM_CHAT_ID`를 넣으면 켜집니다. 알림 전송 실패는 기록만 하며 거래 상태에 영향을 주지 않습니다. 잔고·수익 조회 명령은 두지 않았습니다.

**기존 DB 진단·복구:** `status` 출력의 `books`는 이전 버전이 남겼을 수 있는 장부 불일치를 읽기만 해서 보여 줍니다. 쓰기는 하지 않습니다.

| 항목 | 뜻 | 복구 |
|---|---|---|
| `done_without_switch_effects` | 체결 완료로 저장됐지만 전환 장부(매도대금·매수액)에 반영되지 않은 주문 | 다음 `run`에서 한 번 반영. 거짓으로 완료된 전환은 다시 열고 이벤트를 남김 |
| `done_without_tax_effects` | 완료됐지만 세금 준비금 이동이 빠진 세금 매도·역환전 | 다음 `run`에서 한 번 반영 |
| `orphan_reservations` | 미전송·거부·수동 정리·행 없음 요청에 묶인 진행 중 세금 예약 | 다음 `run`에서 해제하고 감사 기록 |
| `external_funds_migration` | 입금 추적 전이거나 일부만 적용된 외부 재원 표(입금액을 두 번 셈) | 다음 실행에서 두 컬럼 추가·입금액 재구성·출처 표시·완료 표시를 한 트랜잭션으로 처리. 도중에 꺼져도 다음 실행에서 처음부터 다시 적용 |
| `settlement_dates` | 규칙과 다른 저장 결제일 | 다음 원장 동기화에서 다시 계산하고, 그 행의 환율을 비워 다시 받음 |
| `open_requests`의 `unresolved` | 전송됐을 수 있으나 증권사 기록과 아직 맞지 않은 요청 | 자동 확정하지 않음. 기존 잠금 규칙을 따르고, 앱에서 확인 뒤 `resolve` |
| `needs_user` | 근거가 부족한 세무 자료(예: 이전 버전이 출처 없이 기록한 납부) | 출처 없는 납부는 `/tax_paid_fix 0 연도` 뒤 실제 납부를 `/tax_paid 금액 출금\|외부\|기타 연도`로 다시 입력. 출처 모르는 금액이 남을 수 없게 되면 해결 처리되고(해결 기록 남김) 세금 매도 보류가 풀림. 0이 아닌 금액으로 정정하면 어느 부분을 뺐는지 알 수 없어 보류를 유지 |

복구는 멱등이라 여러 번 실행해도 한 번만 반영되고, `repairs_recorded`에 횟수가 남습니다. 세무 자료 문제는 세금 목적 매도만 보류하고 전략 매매는 막지 않습니다.

상태 DB와 종가 이력은 재시작 후에도 유지합니다. 이를 삭제하면 중복 방지 근거가 사라지므로 실거래 중 삭제하지 않습니다. API 토큰 파일은 600 권한으로 저장합니다. 실제 상태·키·계좌 로그는 공유 패키지에 넣지 않습니다.

## 세무 원장과 예상 세액

세금 신고·납부를 대신하지 않습니다. 매년 납부를 준비하는 데 필요한 기록과 추정치를 만듭니다. 근거가 빠진 수치는 항상 "추정"과 누락 원인을 함께 표시합니다.

- **원장 자료:** 계좌의 모든 체결이 대상입니다. 봇 주문뿐 아니라 앱에서 직접 한 매매(QQQM·BRK.B 매도 포함)도 들어갑니다. 증권사 기간 체결내역에서 가져오고, 끝난 미국 정규장의 체결만 기록합니다. 같은 주문이 다른 수치로 다시 오면 덮어쓰지 않고 "중복 체결 불일치"로 남깁니다.
- **원가 방식:** 종목별로 체결 시각 순서인 FIFO입니다. 잔고의 평균단가로 계산하지 않습니다.
- **결제일과 환율:** 결제일은 결제용 달력으로 계산하고 "계산값"으로 표시합니다. 결제일은 뉴욕증권거래소 개장일이면서 연방준비제도 영업일인 날입니다. 그래서 콜럼버스 데이·재향군인의 날처럼 거래는 열리지만 결제가 없는 날은 건너뜁니다(예: 2026-10-09 거래 → 10-13 결제). 주기는 체결일 기준 2024-05-28부터 T+1, 2017-09-05부터 T+2, 1995-06-07부터 T+3입니다. 다음 경우에는 결제일을 만들지 않고 "미확인"으로 둡니다: 달력 범위 밖, 규칙이 없는 날짜, 결제 기간에 임시 휴장(2001-09-11, 2025-01-09 등)이 낀 경우. 증권사가 확인했거나 사용자가 입력한 결제일은 계산값보다 우선하며 자동으로 바꾸지 않습니다. 원장 동기화 때 다시 계산하는 대상은 이 프로그램이 계산해 저장한 값뿐이고, 바뀐 행은 환율을 비운 뒤 감사 기록을 남깁니다. 원화 환산은 그 결제일의 매매기준환율(메리츠 고시환율 API)을 씁니다. 그날 고시가 없으면 앞선 고시를 쓰고 "이전 고시"로 표시합니다.
- **수수료:** 입출금 내역의 해외증권 매매수수료가 정확히 한 건 맞을 때만 반영하고, 아니면 "수수료 누락"으로 표시합니다.
- **연도 귀속:** 결제일 기준입니다. 다음 해 세금을 마련하려고 새해에 판 손익은 그 새해에 들어갑니다.
- **세액 계산:** 연간 손익통산 → 기본공제(기본 250만 원) 1회 → 세율(기본 22%) 순입니다. 원 단위 미만은 버립니다. 수치는 `config.json`의 `tax` 항목, 근거 문구는 코드에 따로 둡니다.
- **다른 증권사 손익:** 입력할 수 있고, 공제는 합산 후 한 번만 적용합니다. 입력이 없으면 "이 계좌만의 추정"으로 표시합니다.
- **배당:** 양도손익에 섞지 않고 연간 합계만 따로 기록합니다(금융소득 종합과세 확인용, 세액은 계산하지 않음).
- **증권사 실현손익 API:** 원가 방식과 환율 시점이 달라 정답으로 쓰지 않습니다. 원화 50만 원과 50%를 모두 넘는 큰 차이(단위 오류, 한 해치 체결 누락 등)만 이상으로 표시합니다. 값이 비슷하다고 검증된 것으로 보지 않습니다.
- **자료 불완전·불일치:** 세금 목적 자동매도만 보류합니다. 대상은 원가·환율·수수료 누락, 단위 이상, 중복 불일치, 원장과 보유 수량 불일치(원장에만 있는 종목은 보유 0으로 비교), 보유 미확인(최근 2일 안의 잔고 스냅샷 없음), 원장 동기화가 없거나 실패했거나 3일 넘게 지난 경우입니다. 정상적인 전략 전환은 막지 않습니다.

텔레그램에서 `/tax`를 보내면 엔진과 같은 보유·완전성 검사로 계산한 예상 세액·자료 상태를 답합니다. 12월에는 예상 세액을, 1월에는 연말 거래·결제를 반영한 재계산을 한 번씩 알립니다. **세금 관련 금액만** 표시하는 예외이며, 정해진 필드로만 그립니다. 전체 잔고·평가금액·수익률·계좌번호·주문번호는 넣지 않습니다. 텔레그램 명령은 허용한 개인 채팅(`TELEGRAM_CHAT_ID`)에서 온 것만 처리하고, 주문·환전은 실행하지 않습니다.

## 세금 준비금 분할 확보

납부 준비 기간(다음 해 1~5월)에 지난해 귀속 세금을 계좌 안에서 나눠 마련합니다. 모든 금액·기한·회차는 **귀속연도별**로 따로 관리합니다.

- **준비 중인 연도:** 지난해는 1~5월 동안, 그리고 최근 2년 안의 연도 중 돈 이동이나 기한이 있는 해는 예상 세액이 다 납부되거나 해제될 때까지 준비 중으로 남습니다. 6월이 되어도 미납 연도를 버리거나 올해로 바꾸지 않습니다. 엔진은 준비 중인 연도 중 확보가 필요한 가장 오래된 연도부터 처리합니다.

- **상태 분리:** 귀속연도별로 다음 상태를 각각 따로 기록합니다. 같은 돈은 한 상태에만 속하고, 모든 이동은 감사 기록이 남습니다.
  - 납부 완료
  - 계좌 원화 준비금
  - 재투자 금지 달러 준비금
  - 세금용 출금(납부 확인 대기)
  - 진행 중 확보(세금 매도·역환전 주문 중)
  - 외부 재원(예정·확보)
- **미확보액:** 예상 세액 − 납부 완료 − 원화 준비금 − 달러 준비금의 보수적 원화 환산액(최근 고시 환율 × 97%) − 출금 대기 − 유효한 외부 재원. 달러 평가액은 원화 준비 완료로 보지 않습니다.
- **회차 일정:** 1~4월 15일, 그리고 최종 확보일입니다. 최종 확보일은 5월 15일과 "그 연도의 납부 기한 − `settlement_buffer_days`(달력 일수, 기본 7일)" 중 이른 날입니다. 기한은 `config.json`의 `tax.payment_deadlines`에 연도별로 넣거나 `/tax_deadline`으로 입력합니다. 다른 연도의 기한을 빌려 쓰지 않습니다. 예전 단일 설정 `payment_deadline`은 그 날짜의 앞 연도(기한 연도 − 1) 귀속에만 적용합니다. 기한이 없으면 "미설정(미검증)"으로 표시합니다.
- **이번 회차 확보량:** 누적 목표 − 이미 확보한 금액입니다. 미래 회차를 앞당기는 것은 `/tax_early on`일 때만입니다.
- **확보 순서:**
  1. 비예약 원화(입금분 포함)
  2. 비예약 달러
  3. 같은 날 전환 매도대금에서 떼어 두기
  4. 그래도 부족할 때만 세금 매도
- **같은 실행의 왕복 매매 방지:** 입금으로 사면서 같은 금액을 세금용으로 파는 일은 생기지 않습니다.
- **세금 매도 조건:** 개장 실행창에서, 진행 중인 전환이 없을 때만 합니다. 판매량은 다음 두 조건을 모두 지킵니다.
  - 이번 회차 부족분까지만 팝니다. 1주 올림 초과분은 부족분 이하일 때만 허용합니다.
  - 사용자가 따로 정한 연간 상한(`/tax_cap`)을 넘지 않습니다. 상한은 원장 추정으로 자동 인상되지 않고 변경 이력이 남습니다.
- **세금 매도 보류:** 상한이 없거나 세무 원장이 불완전하면 관찰 계획만 남기고 알립니다. 이 보류는 세금 작업에만 적용되고, 전략 매매에는 영향이 없습니다.
- **역환전(달러→원화):** 명세의 `mnec_clcd=2`로 구현했습니다. 실계좌 검증 전(`verified.reverse_fx: false`)에는 실행하지 않고, 달러 준비금으로 묶어 둔 채 원화 환전 필요를 알립니다. 검증 뒤에도 다른 신규 요청과 같이, 자기 요청 대조를 먼저 하고 전송 직전에 해외 예약주문을 조회합니다. 활성 예약이 있거나 조회가 실패·불완전하면 보내지 않습니다.
- **외부 재원:** 계획 총액·예정일(`/tax_external`), 계좌 밖에서 실제 확보한 미사용 금액(`/tax_secured`), 계좌 입금 예정(`/tax_deposited`)을 따로 기록합니다. 입금은 입출금 내역에서 금액·날짜(예정일 −1~+7일)가 정확히 한 건 맞을 때만 원화 준비금으로 옮기고, 그전까지는 환전·자동 배분에서 제외해 두 번 세지 않습니다. 예정일 전에는 계획의 남은 금액, 예정일이 지나면 확보한 금액만 유효한 외부 재원으로 봅니다.
- **출금 대조:** `/tax_withdraw`로 등록한 출금만 금액·날짜가 내역과 정확히 한 건 맞을 때 "출금 대기"로 옮깁니다. 무관한 출금은 세금 납부로 보지 않습니다.
- **납부 입력:** `/tax_paid 금액 [출금|외부|기타] [연도]`로 입력합니다. 출처에 따라 출금 대기·외부 재원·기타 자금에서 납부 완료로 옮기고, 출처가 모호하면 처리하지 않고 지정을 요청합니다. 남은 준비금은 `/tax_release 확인 [연도]`로만 일반 현금으로 돌아갑니다.
- **연도 지정:** 상태를 바꾸는 명령은 끝에 귀속연도를 붙일 수 있습니다. 준비 중인 연도가 둘 이상이면 연도가 없는 명령은 처리하지 않고 연도를 요청합니다. 준비 중인 연도가 없으면 계획 명령(재원·상한·조기 확보·기한)은 올해 귀속으로 보고, 돈 이동 기록(출금·납부·정정·해제)은 연도를 붙여야 처리합니다.
- **사용자가 할 일:** 은행 이체와 신고·납부는 직접 합니다. 원화 준비가 끝나면 이체할 금액과 기한을 알립니다.

**텔레그램 세금 명령** (`[연도]`는 생략 가능, 위의 연도 지정 규칙을 따름)

| 명령 | 하는 일 |
|---|---|
| `/tax` | 준비 중인 연도와 올해의 예상 세액·준비 상황 |
| `/tax_external 금액 YYYY-MM-DD [연도]` | 외부 재원 계획 총액·예정일 |
| `/tax_secured 금액 [연도]` | 계좌 밖에서 실제 확보한 미사용 외부 재원 |
| `/tax_deposited 금액 YYYY-MM-DD [연도]` | 외부 재원 계좌 입금 예정(내역 확인 뒤 준비금) |
| `/tax_withdraw 금액 YYYY-MM-DD [연도]` | 세금용 출금 등록(내역과 대조) |
| `/tax_withdraw_cancel 요청번호` | 세금용 출금 취소·재입금 |
| `/tax_paid 금액 [출금\|외부\|기타] [연도]` | 납부 완료 |
| `/tax_paid_fix 총액 [연도]` | 납부액 정정 |
| `/tax_release 확인 [연도]` | 남은 준비금을 일반 현금으로 |
| `/tax_cap 금액 [연도]` | 연간 세금 매도 상한 |
| `/tax_early on\|off [연도]` | 미래 회차 조기 확보 |
| `/tax_deadline YYYY-MM-DD [연도]` | 그 연도의 납부 기한(사용자 입력, 미검증) |

같은 텔레그램 메시지는 여러 프로세스가 동시에 받아도 한 번만 반영합니다. 메시지마다 재확인·계획 변경·처리 기록·수신 위치를 한 트랜잭션으로 저장하고, 답장은 저장 뒤에 보냅니다.

## Mac 밖의 독립 감시

같은 Mac 안의 다른 프로세스나, 같은 공유기 뒤의 기기로는 Mac 정전·네트워크 단절을 알아챌 수 없습니다. 그래서 **다른 호스트**(클라우드 소형 서버 등)에서 도는 감시 서비스를 따로 제공합니다. 감시 서비스에는 증권사 키·계좌 접근·주문 권한이 없고, 주문을 이어받지도 않습니다.

- **거래 Mac 쪽**
  - 실행이 끝날 때마다 상태 하나를 HMAC 서명과 증가하는 순번을 붙여 보냅니다. 거래 판단과 정리 단계가 끝난 뒤, 시간 제한 3초로 보냅니다.
  - 보내는 내용: 실행·업무 완료 시각, 마지막 신호 거래일, 목표 종목, 정렬 여부, 전환 진행 상태, 보류·잠금 코드.
  - 보내지 않는 내용: 수량·금액·수익률·계좌·주문번호·원시 오류·키.
  - 감시 서비스가 멈춰도 매매에는 영향이 없습니다.
- **감시 서비스**(`python -m autotrader.monitor serve`)
  - 서명·보낸 시각(±5분)·순번을 확인합니다. 오래된 메시지를 다시 보내도 정상 상태로 되살아나지 않습니다.
  - 아래 상황을 구분해 텔레그램과 보조 웹훅으로 **직접** 알립니다. 거래 Mac을 거치지 않습니다.
    - 상태 신호 끊김(외부로 아무것도 못 보냄)
    - 살아 있지만 거래 잠김
    - 계속 보류·오류
    - 신호만 오래됨
    - 전환 완료 기한 초과
  - 휴장·단축장·서머타임은 거래소 달력으로 반영합니다.
  - 기한 초과 알림은 안전장치를 풀거나 가격을 쫓지 않습니다.
- **기본값(운영 근거)**

  | 항목 | 기본값 | 근거 |
  |---|---|---|
  | 심박 누락 허용 | 300초 | 60초 실행 5회 |
  | 업무 신선도 | 15분 | |
  | 신호 지연 허용 | 마감 후 2시간 | |
  | 전환 완료 기한 | 신호 다음 정규장의 마감 10분 전 + 15분 | |
  | 같은 알림 반복 | 6시간 | |

  백테스트 수익에 맞춘 값이 아닙니다.
- **설치**
  1. `monitor.example.json`을 `monitor.json`으로 복사하고, `instances`에 거래 Mac의 `status` 명령에 나오는 `monitor.instance` 값을 넣습니다.
  2. 거래 Mac `secrets.env`에는 `MONITOR_URL`(예: `https://감시호스트:8787/heartbeat`, HTTPS 앞단 권장)과 `MONITOR_SECRET`(32자 이상)을 넣습니다.
  3. 감시 호스트 환경에는 같은 `MONITOR_SECRET`, 알림용 `MONITOR_TELEGRAM_BOT_TOKEN`·`MONITOR_TELEGRAM_CHAT_ID`, 선택 사항인 `MONITOR_BACKUP_WEBHOOK`을 넣습니다.
  4. systemd 예제는 `deploy/tqqq-monitor.service`에 있습니다.
- **한계:** 감시 알림도 텔레그램을 쓰면 텔레그램 장애 때 함께 막힙니다. 그래서 보조 웹훅 같은 다른 경로를 하나 두는 것을 권합니다.

## 세금과 현금

이 구현은 세금 신고·납부나 연간 원화 실현손익 계산을 자동화하지 않습니다. 세금·다른 출금에 쓸 원화는 `krw_reserve`로 남겨두거나 별도 계좌에서 마련합니다. `usd_reserve`는 선택적인 고정 현금 여유분이며 양도세 준비금이 아닙니다. 기본값은 0달러이고, 수수료는 `fee_buffer` 0.15%를 포함해 수량을 계산합니다. 고정 5달러 때문에 소액 계좌가 살 수 있는 1주를 못 사는 일을 줄이기 위한 변경입니다. 실제 계좌 수수료·제비용이 이 여유율 안에 들어오는지는 연결 단계에서 확인합니다.

당일 환전 한도는 기본 2천만 원이며 다음 한국 환전 가능 시간에 잔액을 처리할 수 있습니다. 매수는 실제 USD 주문 가능 금액 안에서만 합니다. 재매매 가능 금액이 95% 등으로 제한되면 나머지는 현금으로 남고, 다음 실행 가능 거래일에 다시 투자합니다. 이 대기·정수 주식·현금 여유분은 이상적인 전액 종가 체결 백테스트와 차이를 만듭니다.
